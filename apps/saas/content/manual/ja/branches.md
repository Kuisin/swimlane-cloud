# ブランチとワークフロー

すべてのプロジェクトには、ちょうど 3 種類のブランチがあり、どのプロジェクトでも同じ意味を持ちます。

| ブランチ                           | 表示ラベル | 意味                                                                         |
| ---------------------------------- | ---------- | ---------------------------------------------------------------------------- |
| `main`                             | 公開済み   | 現在リリースされているバージョン。直接編集しない。                           |
| `preview`                          | 承認済み   | レビュー中。これも直接編集せず、プルリクエストがマージされたときだけ変わる。 |
| `<あなた>/<タイムスタンプ>/<キー>` | —          | **あなた**の編集ブランチ。実際の編集はここで行う。                           |

`kaisei/1699999999/flow` のようなブランチ名を自分で入力する必要は一切ありません。**編集を開始**をクリックした瞬間に自動的に作成され、その後は名前を意識せずに作業できます。

## 通常の流れ

1. **編集を開始** — `preview` からあなた専用の編集ブランチを作成します。
2. **編集** — 変更はすべて自動的に保存されていきます。タブを閉じても失われません。
3. **プッシュ** — それまで自動保存された内容を、編集ブランチ上の 1 つの実際のコミットにまとめます。
4. **レビューを依頼** — 編集ブランチから `preview` へのプルリクエストを作成します。編集権限のある人がレビューしてマージします。
5. **公開**（オーナーのみ） — `preview` の内容をスナップショットし、バージョンとしてタグを付け、`main` に反映します。詳しくは[バージョンと公開](?section=versions)を参照してください。

## なぜ `main` や `preview` を直接編集できないのか

レビュアーが `preview` で見るものが常に実際にレビューされたものであり、`main` で公開されているものが常に実際に公開されたものであるようにするためです —— レビューされていない変更が紛れ込むことはありません。どちらかを直接編集しようとすると、代わりに編集ブランチを開始するよう案内されます。

## 編集中に他の人がプッシュしていた場合

プッシュには保護がかかっています。編集している間にブランチが（誰かが先にプッシュして）変わっていた場合、上書きせずにプッシュは拒否されます。「ブランチが更新されました」というメッセージが表示されるので、更新を取り込んでから変更を再度適用してください。

## レビュー中の編集ブランチはロックされる

編集ブランチからプルリクエストを開くと、そのブランチはマージまたはクローズされるまでロックされます。これはレビュアーが承認した内容をそのまま維持するためです。その間も、別のファイルや別のブランチに切り替えることは可能です。
